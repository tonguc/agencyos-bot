## 1. Executive Summary

AgencyOS işlevsel olarak çalışıyor ancak teknik borç birikmiş bir codebase. Son 60 commit'in %60'ı `backend/`, sürekli `fix(scorer)`, `fix(search)`, `fix(icp)`, `fix(collector)` tekrar eden iterasyon görülüyor — aynı modüller defalarca kırılıyor. Sıfır test, sıfır CI, "changeme" default API key prod'da silent pass ediyordu.

En yüksek riskler maliyet (Apify+Claude retry-storm/idempotency yok), trust-breaking UX (voice asistan kullanıcıya "tarama başladı" diyor ama hiçbir şey yapmıyor) ve veri bütünlüğü (state machine guard yok, dedup race condition).

Bu denetim **51 ham bulgu → 46 unique** çıkarttı; 14 küçük güvenli patch uygulandı (5 commit cost, 4 commit observability, 3 commit security/correctness, 2 commit cleanup). Geri kalan 32+ bulgu büyük yapısal değişiklik gerektiren task-level idempotency, ARQ retry, state machine ve dedup race patch'leri ile aynı sprint'te yapılmalı.

## 4. Açık P0 Backlog (büyük yapısal — ayrı sprint)

### P0-A — Task-level idempotency (audit/outreach/proposal job)
**Sorun:** Route-level guard pending|running job'u yakalar; ama task ortasında fail edip ARQ'nun retry'ı tetiklenirse `run_audit()` ikinci kez çalışır → ikinci `AuditRepository.create()` → duplicate DB kaydı + 2× Claude maliyeti. Aynı problem outreach + proposal için.
**Etki:** ARQ `max_tries>1` açılamıyor — şu an her transient fail = job kaybı. Ya retry yok (kullanıcı manuel re-trigger) ya da retry açıkken cost patlaması.
**Plan:**
1. `audit_service.run_audit()` başında `AuditRepository.get_latest_for_lead(lead_id, max_age=...)` kontrolü → varsa skip.
2. Aynı pattern outreach/proposal'da.
3. Sonra `worker.py`'de `max_tries=2`, `retry_delay=10` aç + `arq.Retry` raise yalnız transient class'larda (`anthropic.APIConnectionError`, `httpx.ConnectError`).
**Dosya:** `services/{audit,outreach,proposal}_service.py`, `repositories/{audit,outreach,proposal}.py`, `jobs/worker.py`.
**Risk:** Orta — "force regenerate" path'i de eklenmeli (query param `?force=true`).

### P0-B — Apify 402 (kredi tükendi) explicit handling + admin alarm
**Sorun:** `lead_collector.py`'de 402 RuntimeError olarak yukarı gidiyor, frontend'de "0 sonuç" + generic hata mesajı. Admin alarm yok, kredi tükenmesinden saatler sonra fark ediliyor.
**Plan:**
1. `_run_apify` 402'yi spesifik exception ile yakala.
2. Settings'e `APIFY_LOW_CREDIT_THRESHOLD` + günlük kontrol task'ı.
3. UI'a "Apify krediniz düştü" persistent banner.
4. Admin'e Telegram bildirimi (bot zaten var).
**Dosya:** `core/lead_collector.py`, `api/routes/settings.py`, `bot/handlers.py` (notify channel).
**Risk:** Düşük (yeni feature, mevcut akışı bozmaz).

## 5. Açık P1 Backlog

### P1-A — State machine guard (Lead + Job status)
**Sorun:** Lead `status` String(50), runtime check yok. "Kapandi" → "Mesaj"a geri çevrilebilir, outreach yeniden tetiklenir. Job statüsü için de aynı.
**Plan:** Pydantic `Literal[...]` schema + service layer transition table (whitelist).
**Dosya:** `schemas/lead.py`, `services/lead_service.py`, `repositories/job.py`, optional Alembic CHECK constraint migration.

### P1-B — Phone-only dedup race + name fallback unification
**Sorun:** `lead_service.collect_and_save` sadece phone dedup; name fallback yalnız `search.py:_enrich_lead_ids`'te var. İki kanal eşzamanlı → race → duplicate lead.
**Plan:** `LeadRepository.find_or_create()` helper — phone+name normalize edilmiş key. UPSERT semantiği. Aynı transaction içinde lock veya phone+name tekil index.
**Dosya:** `repositories/lead.py`, `services/lead_service.py`, optional unique index migration.

### P1-C — `core/utils.py` ↔ `backend/core/utils.py` duplication drift
**Sorun:** İki dosya near-identical (Claude client, safe_json_parse). Bir taraf değişince diğeri unutulur (Patch 2'de iki kez timeout eklemek zorunda kaldık).
**Plan:** Root `core/` legacy → bot HTTP-only olduğundan kullanılmıyor. Önce import grep ile kullanıcılar doğrulanır → kullanıcı yoksa root `core/` silinir; varsa `backend/core/`'ı root'a sembolik referans.
**Dosya:** `core/*` (root) — silinme adayı.

### P1-D — Voice asistan SCRAPE_TOOL kalıntısı
**Sorun:** Tool tanımı (`SCRAPE_TOOL`) hâlâ Claude'a gönderiliyor (`tools=_CACHED_TOOLS`), prompt artık çağırma diyor. Cache'li olduğu için cost düşük ama mental yük + olası ileride değişiklik bug riski.
**Plan:** `tools` parametresini `messages.create`'ten kaldır, `SCRAPE_TOOL` ve `ScrapeAction`/`VoiceScrapeAction` type tanımlarını sil. ~30 satır temizlik.
**Dosya:** `backend/api/routes/voice.py`, `frontend/lib/api.ts` (ScrapeAction type).

### P1-E — SerpAPI fallback güvenilirliği + geo coordinates
**Sorun:** Apify fail olduğunda SerpAPI devreye girmeli, ama `ll` parametresi için şehir/ilçe geocode edilmiyor → tüm Türkiye'de arama + agresif location filter.
**Plan:** Şehir+ilçe → lat/lng cache (statik dosya başlangıç olarak; 81 il + büyük ilçeler ~500 entry yeter).
**Dosya:** `core/lead_collector.py`, yeni `core/geo_lookup.py` (statik JSON).
